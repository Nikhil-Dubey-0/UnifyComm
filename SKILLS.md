The skills needed to build UnifyComm, what each is used for, and the patterns and pitfalls that apply to this project. Versions and facts were checked on the web on **2026-10-06**. Re-check anything version-specific before relying on it in a later month.

- **Part A** covers engineering skills (for Claude Code and the team).
- **Part B** covers Claude Code agent skills: which to use, which to install, and which project skills to create.

`ARCHITECTURE.md` decides *what* to build. This file covers *how to build it well*.

### A1. Python tooling: uv, ruff, pytest
- **Use:** `uv init`, `uv add`, `uv sync`, `uv run`. Commit `uv.lock`; it pins exact versions (important for transformers, see A6).
- **CPU torch with uv:** add an explicit PyTorch CPU index in `pyproject.toml` (`[[tool.uv.index]]` named `pytorch-cpu`, URL `https://download.pytorch.org/whl/cpu`, `explicit = true`, then `[tool.uv.sources] torch = { index = "pytorch-cpu" }`). Without it, uv may resolve a large CUDA build.
- **ruff** for both formatting and linting. **pytest** with `pytest-asyncio` (`asyncio_mode = "auto"`).
- **Pitfall:** Python 3.13 is the installed version. Current PyTorch (2.14.1, Sep 2026) supports 3.10–3.14, so 3.13 is fine.

### A2. FastAPI + Pydantic v2
- **Version:** FastAPI 0.142.x (released 2026-09-30), Pydantic 2.13+.
- **Patterns we use:** `lifespan` context manager to start and stop the `EventBridge`. Dependencies for DB session and current agent. Routers per resource. One exception handler for domain errors. `pydantic-settings` for `.env`.
- **WebSockets:** native `@app.websocket("/ws")`, auth from a query token, a hub class holding connections, and a send loop protected against slow clients (drop on send error).
- **Pitfall:** run a single uvicorn worker; the WS hub is in memory.
- Docs: https://fastapi.tiangolo.com/ · release notes: https://fastapi.tiangolo.com/release-notes/

### A3. SQLAlchemy 2 async + asyncpg + Alembic
- **Patterns:** `create_async_engine("postgresql+asyncpg://...")`, `async_sessionmaker(expire_on_commit=False)`, typed `Mapped[...]` models. Alembic created with the **async template** (`alembic init -t async migrations`). Review every autogenerated migration (partial unique indexes and CHECK constraints are often missed).
- **Why asyncpg:** psycopg 3's async mode cannot run on Windows' default `ProactorEventLoop`; asyncpg works with it. Using one driver for ORM and LISTEN avoids the problem completely.
- **Pitfall:** never share an `AsyncSession` across concurrent tasks. Use a fresh session per job and per request.

### A4. PostgreSQL patterns
- **Idempotency:** partial unique index `(provider, external_message_id) WHERE external_message_id IS NOT NULL` with `INSERT ... ON CONFLICT DO NOTHING RETURNING id`. No row back means a duplicate.
- **Job queue:** `SELECT ... FOR UPDATE SKIP LOCKED LIMIT 1` inside an `UPDATE ... RETURNING` to claim, plus a lease (`locked_at`) that expires after 5 min, retries with exponential backoff, and `failed` after `max_attempts`. Handlers must be idempotent. This is the same model as Sidekiq, BullMQ and pgqueuer.
- **LISTEN/NOTIFY:** `pg_notify('uc_events', json)` inside the writing transaction; it is delivered only on commit. Payload limit is 8,000 bytes, so send IDs only. The listener needs its own dedicated connection (asyncpg `add_listener`). Reconnect with backoff and tell clients to resync, since notifications sent while disconnected are lost.
- **Time:** `timestamptz` everywhere; convert to IST only at the edges. Windows Python has no system timezone database, so the backend depends on `tzdata` (added in Session 1, approved by the user) for `ZoneInfo("Asia/Kolkata")`.
- References: https://github.com/janbjorge/pgqueuer · https://www.mgaillard.fr/2024/12/01/job-queue-postgresql.html

### A5. Auth: JWT + Argon2
- FastAPI's docs now use **PyJWT** for tokens and **pwdlib[argon2]** for password hashing (passlib is no longer recommended). Use `OAuth2PasswordBearer` for REST and a `?token=` query parameter for the WebSocket.
- Keep it small: two roles (`agent`, `admin`), 12-hour tokens, no refresh tokens.
- Docs: https://fastapi.tiangolo.com/tutorial/security/

### A6. Hugging Face Transformers v5 + PyTorch inference
- **Versions:** transformers 5.x (v5.0.0 released 2026-01-26; 5.18.0 on 2026-09-30). The team's models were saved with **5.0.0**. PyTorch 2.14.1.
- **v5 changes that matter here:** safetensors is the only serialization format. Tokenizers are consolidated onto the Rust-backed path with one tokenizer file. `use_auth_token` became `token`. `encode_plus`/`batch_encode_plus` are deprecated; call the tokenizer directly. Weekly minor releases have shipped breaking changes, so **pin the exact minor version in `uv.lock`** and upgrade deliberately.
- **Intent model:** encoder `sentence-transformers/all-MiniLM-L6-v2` (Apache-2.0; designed for attention-masked mean pooling) plus a custom `Dropout(0.1) → Linear(384, 213)` head, `max_length 64`. Mirror the training notebook's class exactly; pooling choice changes predictions. Golden tests decide.
- **Sentiment model:** `cardiffnlp/twitter-roberta-base-sentiment-latest` via `AutoModelForSequenceClassification`, labels `negative/neutral/positive`, CC BY 4.0. Apply the model card's preprocessing (`@mention → @user`, URL → `http`). Pin the Hub `revision`.
- **Inference hygiene:** load once per process, `model.eval()`, `torch.inference_mode()`, `torch.set_num_threads(4)`, batch inputs, truncate, run in `asyncio.to_thread` from async code, and record the weights' sha256 as `model_version`.
- **Pitfall:** never import these packages from the API process (ARCHITECTURE D3).
- Docs: https://github.com/huggingface/transformers/blob/main/MIGRATION_GUIDE_V5.md · https://huggingface.co/cardiffnlp/twitter-roberta-base-sentiment-latest · https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2

### A7. Model training and evaluation (Plan B only)
- Separate `ml/` environment with **CUDA** torch for the GTX 1650 (4 GB VRAM). Batch 32 at `max_length 64` with a 22M-parameter encoder fits; use fp16 autocast if memory is tight.
- Reproduce the documented two-stage recipe (ARCHITECTURE §8.2) with the **same label mapping**. Use separate learning rates for encoder and head through optimizer parameter groups.
- Evaluate on the official **test** splits, not validation. Report accuracy, macro-F1 and weighted-F1. Explain the macro vs weighted gap: Banking77 test is balanced, so a large gap means predictions are leaking into CLINC labels.
- Set seeds, save `final_metrics.json`, and keep the training log for the report.
- Datasets: Banking77 (13,083 queries, 77 intents) and CLINC150 `plus` (150 intents + out-of-scope). Verify current Hub dataset IDs and that they load without legacy loading scripts.

### A8. OpenAI Responses API
- **Models (Oct 2026):** `gpt-6-astra` (flagship, $10/$50 per M tokens), `gpt-6.1-sol` (near-flagship, $2/$10), **`gpt-6-luna`** (efficient, $0.10/$0.50, our default). `gpt-5.4-nano`, `gpt-5.1` and `gpt-5.3-codex` are deprecated and will be removed from the API on 2027-04-01. Keep model IDs in `.env`.
- **Pattern:** `AsyncOpenAI(timeout=20, max_retries=1)`; `await client.responses.parse(model=..., input=[...], text_format=DraftOutput, store=False)`; read `response.output_parsed`. Pydantic models define the output schema (structured outputs), so there is no JSON string parsing.
- **Pitfalls:** optional fields in structured-output schemas need care (prefer required fields with empty defaults in the prompt contract). Always set a timeout, catch every OpenAI exception and map it to `LLMUnavailable`. Never log prompts that contain customer text.
- Docs: https://developers.openai.com/api/docs/models · https://developers.openai.com/api/docs/guides/structured-outputs · https://github.com/openai/openai-python/blob/main/helpers.md

### A9. LLM safety for customer-support replies
- **Prompt injection:** customer messages are untrusted. Wrap them as quoted data in the prompt, tell the model to ignore instructions inside them, and keep a human in the loop (no auto-send). The compliance gate still runs on whatever the agent sends.
- **PII:** redact card numbers, Aadhaar-format numbers, phones, emails and OTP/PIN codes before sending text to OpenAI. Use `store=False`.
- **Hallucinated commitments:** the prompt forbids promising refunds or outcomes. `verify_hints` lists the facts the agent must check.
- **Evaluation:** keep 10–15 fixed conversations and review draft quality by hand whenever a prompt changes.

### A10. Next.js 16 + TypeScript + Tailwind + shadcn/ui
- **Version:** Next.js 16.3.x (16 is the active line; App Router is where new features land).
- **Patterns:** App Router with route groups `(auth)` and `(workspace)`. The workspace is client-rendered (`"use client"`) because it is live and authenticated. No Next.js API routes or server actions as a second backend; FastAPI is the only backend.
- **Demo:** run `npm run build && npm start`; it uses far less memory than `next dev` on a 7.3 GB machine.
- Docs: https://nextjs.org/docs · https://ui.shadcn.com/docs

### A11. TanStack Query v5 + typed API client
- **Versions:** `@tanstack/react-query` 5.10x. `cacheTime` is now `gcTime`.
- **Typed client:** `openapi-typescript` generates `schema.d.ts` from FastAPI's `openapi.json`; `openapi-fetch` gives a typed `client.GET("/api/conversations/{id}", ...)`. An `npm run gen:api` script plus `tsc --noEmit` turns backend contract drift into a build error.
- **Patterns:** query keys as in `CLAUDE.md`. Mutations (send, patch) invalidate affected keys on success. Generate the `Idempotency-Key` (`crypto.randomUUID()`) once per compose action, not once per click.
- Docs: https://tanstack.com/query/latest · https://openapi-ts.dev/openapi-fetch/

### A12. WebSocket client patterns
- One socket per browser session, created after login. Reconnect with exponential backoff (1 s → 30 s with jitter). On `open` after a reconnect, and on a `resync` message, invalidate all queries. Show a small connection indicator.
- Events only invalidate queries; the REST refetch is the state.

### A13. Twilio WhatsApp
- **Sandbox facts:** each test phone must send `join <code>` to the sandbox number, the sandbox session expires after **3 days**, and joining also opens a customer-service window.
- **24-hour rule (Meta):** free-form messages are allowed for 24 h after the user's last inbound message. Outside that window only approved templates are allowed, and Twilio returns error **63016**. ARCHITECTURE rule `whatsapp.session_window` blocks these before Twilio is called.
- **Webhook security:** validate `X-Twilio-Signature` with the Twilio SDK's `RequestValidator(auth_token).validate(url, form, signature)`. Build `url` from a fixed `PUBLIC_BASE_URL` plus the path, never from proxy headers. A URL mismatch is the usual cause of failures behind ngrok.
- **Tunnels:** free ngrok URLs change on every restart (sessions are time-limited). Update `PUBLIC_BASE_URL` and the Twilio console together.
- Docs: https://www.twilio.com/docs/whatsapp/sandbox · https://www.twilio.com/docs/usage/webhooks/webhooks-security · https://www.twilio.com/docs/api/errors/63016

### A14. Email over IMAP/SMTP (Gmail)
- Gmail IMAP/SMTP still works in 2026 with **OAuth 2.0 or an app password**. App passwords require **2-Step Verification**. Google Workspace accounts (college accounts) may block basic auth and app passwords entirely, so **use a personal Gmail account** for the demo.
- IMAP: poll `UNSEEN` in INBOX every 20 s from the worker (stdlib `imaplib` in `asyncio.to_thread`, or `aioimaplib`), use `Message-ID` as the external ID, then mark as seen. Parse with stdlib `email` (`policy.default`), prefer `text/plain` parts.
- SMTP: `smtp.gmail.com:465` (SSL) or `587` (STARTTLS). Set `In-Reply-To` and `References` so replies thread in the customer's mail client.
- Sources: https://support.google.com/accounts/answer/185833 (app passwords) · https://www.getmailbird.com/gmail-oauth-changes-app-password-phase-out/

### A15. Contact data handling
- Phones: `phonenumbers` (Python port of libphonenumber). `parse(raw, "IN")`, `is_valid_number`, `format_number(..., PhoneNumberFormat.E164)`. Strip `whatsapp:` first.
- Emails: trim and lowercase for matching, keep the original for display.
- Email body cleanup before classification: drop quoted lines (`>`), "On … wrote:" blocks, forwarded headers and signatures after `-- `. Unit-test it with real Gmail and Outlook samples. Keep the original body for display.
- Luhn check for card-number detection (content rule and redaction).

### A16. Indian messaging compliance and WhatsApp policy
- **TRAI TCCCPR (2018, amended Feb 2025):** promotional messages only between **09:00 and 21:00 IST**. Transactional and service messages (from an existing relationship or a user-initiated action) can reach DND numbers at any time. SMS headers carry type suffixes `-P` / `-S` / `-T` / `-G` (May 2025).
- **Our modelling:** purpose `proactive` ≈ promotional (DND, time window and opt-in rules apply). `service_reply` ≈ service (only opt-out, WhatsApp window and content rules apply).
- **Report wording:** describe consent and DND as local application data simulating the registry. Read and cite the primary TRAI text before quoting it.
- Sources: https://www.trai.gov.in/sites/default/files/2025-02/Regulation_12022025.pdf · https://www.telerivet.com/blog/india-sms-compliance-trai-dlt-registration-and-tcccpr-guide

### A17. Testing
- **Backend:** pytest + pytest-asyncio. `httpx.AsyncClient(transport=ASGITransport(app))` for REST. Starlette `TestClient` for WebSocket tests. A real PostgreSQL test database (no SQLite; we rely on Postgres features). `process_one_job()` runs worker jobs inline.
- **Contract tests:** intent labels ⊆ intent map; OpenAPI → TS types compile.
- **Boundary test:** import `app.main` in a subprocess and assert `"torch" not in sys.modules`.
- **E2E:** Playwright drives the simulator and the workspace side by side (the `webapp-testing` skill in Part B helps).

### A18. Windows-native development
- PowerShell 5.1 has no `&&`; use `;` or `if ($?) { ... }`. Quote paths with spaces.
- PostgreSQL 17: `winget install PostgreSQL.PostgreSQL.17`. `psql` lives in `C:\Program Files\PostgreSQL\17\bin` (add to PATH).
- No Docker on this machine and 7.3 GB of RAM: run services natively; never run training and the full stack together.
- Line endings: set `git config core.autocrlf true` or add `.gitattributes` so shell scripts keep LF.
